# Task-shaped Pack evaluation protocol

Status: **design only; no experiment is reported here**. The fixture assertions are hypotheses, not observations. No quality improvement or other benefit may be claimed without the corresponding experiment and results; a successful parse or a plausible example is not such evidence.

## Question and comparisons

Test whether task-derived authoring guidance changes the usefulness and fidelity of Packs for varied author tasks, and separately whether the resulting Packs help on downstream tasks. These are two different comparisons:

1. **Authoring:** the same model and authoring request with either (A) no Pack Creator, no #48 content and no new task-derived guidance, or (B) the candidate Pack Creator including #48 and the new guidance. This measures the combined intervention, not the isolated effect of the new Practice or #48. Include an additional #48-without-new-guidance arm if the new Practice's incremental effect is to be estimated; otherwise do not attribute differences to it.
2. **Downstream:** for each generated Pack, compare the same model on matched tasks with the Pack available versus no Pack. Run this comparison separately for Packs from each authoring arm. It estimates the effect of making that generated Pack available, not an independently proven effect of the authoring guidance.

## Fixed inputs and isolation

Before running, freeze and record the candidate Creator commit, the exact #48-only revision if used, all source materials, author prompts, downstream tasks, scoring rubrics, model/provider and exact model version, system/developer instructions, decoding settings, tool versions, and environment. Use the same capable model version for every arm and both stages. Start a fresh isolated conversation and workspace for each run; do not carry summaries, cached retrieval results, hidden files, or previous outputs across conditions. Fix permissions and available tools across matched arms. Disable external browsing and network access unless the task explicitly supplies it; expose the same task materials and tool affordances to every condition. Do not execute Pack scripts unless the current task explicitly authorizes them.

Give authoring arms the same requested Pack outcome, source facts and existing format contract, including required metadata. Only the Creator guidance available to the author changes. In A, remove Creator content, #48-derived guidance, this new guidance, and paraphrased equivalents from prompts, retrieval stores, workspace files and model-visible context; retain only the neutral task and format contract. In B, supply the frozen candidate Creator through a documented, identical mechanism on each run. For the optional incremental arm supply only the frozen #48-era Creator, without the new Practice or equivalent guidance. Record exactly what was actually delivered, including retrieved Practice IDs and text when retrieval is used; a retrieval miss is an outcome, not permission to silently inject the missing guidance. Do not claim A is free of any influence from unknown model pretraining.

Use the conservation, oral-history, and mixed exercise examples in `workflows.yaml` as development cases, not as the only evaluation set. Before generating Packs, assemble and freeze an independent held-out set of actual author requests and source packets spanning unrelated domains, decisions, and mixed real/simulated or other overlapping needs. Include short and detailed source packets, explicit domain constraints, meaningful omissions, and tasks that do not benefit from the same body shape. Record provenance and permission for real material, redact sensitive data, and specify what each source supports. Prepare held-out downstream requests and answer keys from those packets before seeing generated Packs. Keep evaluation tasks, answer keys, fixtures, and this protocol out of model-visible workspaces and retrieval indexes. Do not fabricate a benchmark or report a sample size until the available cases are documented.

## Procedure and randomization

For each held-out author task, generate one Pack per authoring arm per predeclared seed, using matched settings and seed where supported. Predeclare the number of tasks and seeds and an analysis plan before running; retain all attempts, failures, token/tool limits and stop reasons. Randomize arm order within each task and seed using a recorded randomization seed, balancing order where possible. A seed does not guarantee identical model behavior: record provider nondeterminism and any unavailable controls.

Validate each generated Pack against the same existing format contract and preserve the complete artifact, logs, prompt, source revision and validation result. Structural failure is an outcome; do not repair only one arm or silently discard it. If repair is part of the intended workflow, predefine the same repair budget and feedback for every arm and retain both initial and repaired artifacts. Do not impose a fixed body template, taxonomy, mandatory analysis dimensions, or questionnaire as a condition of success.

For each resulting Pack, run the same downstream model and task in fresh paired contexts: Pack available through the normal documented selection mechanism, and no Pack available. Keep the source materials and tool permissions identical between each pair; expose the generated Pack only in the Pack condition, and never expose the Creator or the answer key. Record whether and which Practice was actually selected and delivered, along with context truncation and retrieval errors. Randomize paired order with a recorded seed; run the same predeclared downstream seeds and budgets for both conditions. If no retrieval mechanism is available, predeclare a consistent direct-inclusion mechanism and identify the result as direct-inclusion rather than retrieval evidence. Treat failed delivery and invalid Packs as outcomes under the predeclared policy, not as successes or silently excluded cases.

## Outcomes and reporting

Have at least two independent domain-qualified reviewers, blinded to authoring arm and downstream Pack condition where feasible, score outputs against the frozen task-specific evidence and answer keys. Record reviewer identity or role, conflicts, blinded artifact IDs, disagreements and adjudication. Report blinding failures. Reviewers should assess whether the output:

- preserves source-supported domain-specific facts and action boundaries, including all relevant parts of a mixed task;
- provides decisions and detail useful for the actual reader and situation without forcing a universal form or category;
- distinguishes missing information and author inference from source facts, without inventing limits, authority, timings, actors or other unsupported details;
- respects the existing Pack format and avoids unsafe actions; and
- for downstream responses, reaches the task-specific decision or handoff and uses any delivered guidance appropriately.

Predefine a scoring rubric and per-case expected and forbidden behaviors, including how partial credit and unsafe or unsupported assertions are counted. Report per-case paired results, denominators, failures, reviewer agreement and uncertainty alongside aggregate differences, separately for format, content fidelity, retrieval/delivery and downstream behavior. Do not merge these into a single validation claim. Preserve run IDs, exact prompts, model and tool versions, seeds, generated Pack hashes, selected Practice IDs, outputs and reviewer records so another evaluator can reproduce the procedure, subject to model availability and source permissions. Report missing runs, deviations, exclusions and their reasons; distinguish reproducibility of the procedure from deterministic reproduction of model outputs.

Risks include small or unrepresentative samples, leakage from development examples or prior model exposure, correlated cases, subjective scoring, model/provider drift, unblinded formatting, differential retrieval or context limits, and unsafe advice. Use holdouts, paired runs, blinded independent review and explicit safety review to reduce—not erase—these risks. Stop or contain any real-world action that could harm people, collections, services or data; simulated tasks must remain simulated. A null, mixed, or adverse result is reportable. Do not infer general benefit, causality for the new Practice alone, or real-world safety beyond the actual comparison and observed evidence.

## Exploratory authoring smoke (2026-11-11)

Three independent planner sessions received the same constructed museum oral-history task: research consent did not establish online-publication consent, incomplete authorization required checking with the museum's authorization lead, and current withdrawal status needed checking. The source specified neither a verification deadline nor an audio-deletion requirement. Each session was asked for two Practices, so this smoke cannot test whether the model would independently choose that split.

The no-guidance session read no Pack files; the prior-guidance session read the existing decision-outcome and decomposition Practices; the updated-guidance session read those two plus `derive-pack-content-from-task-needs`. All three separated publication scope from current consent status, preserved the need to verify uncertain permission, and did not impose an invented deadline or deletion step. The no-guidance output used a prose field list rather than a directly usable YAML frontmatter block; the other two provided YAML blocks. The updated-guidance output explicitly kept the shared publication restriction in each Practice and stated that its retrieval and behavior were untested. This single observation does not establish that the new guidance improves a capable model.

All sessions used the same configured planner role (`openai/gpt-6.1-sol:medium`), but their actual execution model identity was not exposed. One constructed task, one sample per condition, no blinding, no held-out cases, no downstream task, and no validation of the generated files; these results are not the experiment specified above. The prior and updated guidance were directly supplied, not retrieved. The authoring prompt and material were identical apart from the listed guidance, but agent instructions and tools were not independently audited for hidden differences.
