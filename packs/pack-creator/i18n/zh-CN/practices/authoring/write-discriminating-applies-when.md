# `applies_when` 要能选中这一条，而不是整个主题

## 适用场景

准备写完 `applies_when`
时，问问读者遇到什么事才会需要这一条 Practice。它要回答的问题应该已经明确；现在写具体情境，不是写所属领域。整套 Pack 在哪些时候有用，应在之前考虑；找到本条以后怎样做、何时停止，留在“具体指导”中。

## 具体指导

说清读者即将决定或处理什么、会影响什么，以及什么条件下本条才有用。`applies_when`
只写适用条件；必要背景放在已有的“适用场景”章节，不用另加摘要或介绍。如果另一条 Practice 也可能匹配，在测试数据或作者笔记中记录一个看似相关却不适用的请求，再把决定该选哪一条的事实写入
`applies_when`。删除不能缩小适用范围的主题标签。初次阅读的人能判断何时选本条、何时改选最相近的另一条时，就可以停止。

## 反模式

安全 Pack 分别处理 token 存储、轮换和请求校验。作者为获得更高召回，在每条都写“处理身份验证时适用”。查询在哪里保存新的第三方 token 时，系统没有任何信号优先选择存储规则，看似高召回实际无法分流。

## 原因

只有触发条件指向可区分的决定，召回才能可靠选择一条 Practice。主题标签会让相邻条目竞争同一查询，并在行动时加入无关指导。

## 例外与边界

不同技术或角色在相同条件下面对同一决定时，可以由一条 Practice 覆盖。不要把实现步骤塞进触发条件，只为显得具体。如果一个触发条件中仍有两个决定，应先拆 Practice。

## 示例

数据库运维 Pack 有一条处理线上 schema 变更中新增索引。迁移记录显示，风险发生在索引可能扫描或锁住已有数据的表时，而不是每次数据库变更。作者围绕该条件写
`applies_when`，排除只改元数据的迁移，把索引构建步骤留在指导中。
