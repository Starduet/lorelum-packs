# 本地化要便于人工审阅，但不能产生第二套运行时含义

## 适用场景

新增或更新译文时，要让目标语言的审查者自然读懂同一套指导，不能把译文变成规则不同的第二套 Pack。Practice
ID、运行时使用的文件和要帮助读者作的决定，都仍以同一份权威原文为准。

## 具体指导

翻译决定含义，不照搬英文语序。保持 Practice 和反模式所对应的身份、触发条件、必需动作、停止点、例外、直接原因和案例关系不变；不熟悉的习语可换成目标语言的自然表达。按仓库的本地化布局保存译文：译文与原文 ID 对应，但不需要复制运行时 YAML 元数据。译文不进入权威运行时输入，并应记录对应的原文修订。请目标语言审查者同时核对可读性和意义。所有译文都与当前原文一致、可审查，并能追踪到唯一一条权威 Practice 时停止，不能为“更实用”而新增本地语言专属运行时规则。

## 反模式

合规 Pack 的原文要求按适用政策规定的期限保留客户记录，并在规则冲突时上报。某地区审查者希望看到具体数字，翻译者知道一个业务部门常用七年，于是只在译文加上“七年”。这个补充看似方便，却会变成第二条规则，可能在部门政策变化后继续存在，也可能与其他读者适用的原文条件冲突。

## 原因

自然译文能帮助人发现原指导是否含糊、领域判断是否有错。如果译文另有一套运行时规则，同一 ID 就可能让读者作出不同决定，修正时也没有唯一依据。

## 例外与边界

译文可以用明确标注为非权威正文的说明解释术语、法规名称或案例，但不能改变决定。真正影响运行时的地区规则应成为带明确触发条件的权威 Practice 或独立 Pack。本条不要求逐句对齐。

## 示例

数据库运维 Pack 在恢复访问控制时使用“fail
closed”。中文直译不清楚，翻译者改成：“无法确认权限状态时，继续拒绝访问，并请操作人员处理。”Practice 和反模式 ID 对应关系不变，示例仍保持相同恢复顺序，本地化记录指向已审查的原文修订，也没有把中文文件放进运行时 Pack 根目录。
