# 没有未决判断，就不要扩大调查范围

## 适用场景

已经找到要改的文件、符号或行为，却还想继续阅读来熟悉仓库时，先问：下一份材料能改变什么具体选择？如果目标还没找到，先定位目标。已知来源对应该实现的行为有分歧，就先确认应以哪份为准。

## 具体指导

1. 打开下一份材料前，先说清还要决定什么：在哪里改、哪个组件负责、必须实现什么行为、用什么针对性的检查，或是否要重做计划。
2. 打开能直接改变这个选择的那一份材料，可以是代码、测试、配置、文档、日志或相邻实现，再根据读到的事实作决定。
3. 一次只追一个未决依赖。一个已隔离在单个 handler 及其序列化器里的 bug，需要的是这两处，而不是修复前把每个相邻端点都摸一遍。
4. 当证据揭示重要的新增对外接口或行为、共享状态、风险或验证需要时，停止局部调查并据此重做计划。

熟悉仓库、读了很多文件或画完调用图，都不能证明局部改动安全。明确要实现的行为、负责的组件、修改位置和检查方法，且继续阅读不会改变这些答案时，就停止调查。

## 反模式

用户要求把设置页的保存按钮从灰色改成蓝色。Agent 找到了页面，看到按钮用一个共享 variant，并定位了该 variant 读取的颜色 token。它没有去判断 token 的语义允许局部覆盖还是全局修改，而是打开了每个 Button 使用方、旧主题迁移、无关页面样式、大而全的端到端套件和架构笔记。这些材料改变不了任何颜色决策，消耗上下文，还淹没了真正定义这次编辑的两个来源。

## 原因

调查只有在能改变下一个决策时才有用。阅读做不到这一点的来源，只会把不确定性变成拖延、浪费上下文，并让无关观察与正确变更所需的少量事实竞争注意力。

## 例外与边界

遵循工作环境已提供的适用指令，不要为了重现未知的指令发现机制而人工扫描仓库。人身与运行安全、信息安全、数据、兼容性、迁移、发布或明确要求的审计可能需要多查，但每份额外材料仍须回答一个具体问题，说明影响到哪里、有什么限制。目标找不到就搜索；直接证据显示改动超出已接受范围时，重做计划，不要继续扩大调查。

## 示例

用户要求修正发票预览里的货币标签。Agent 定位预览组件，看到标签来自一个共享格式化器，就读取该格式化器及其聚焦测试。格式化器已经收到带 locale 的货币代码，于是 Agent 只修正一处标签映射并跑格式化器测试；不去检查每个发票消费方或历史账单迁移。如果格式化器反而揭示持久化的货币代码不匹配，Agent 停下来重做计划——任务已不再是局部标签修正。
