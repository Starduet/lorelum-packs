# 没有未决判断，就不要扩大调查范围

## 适用场景

Agent 已经定位到要改的文件、符号或行为，却准备继续读取更多代码、测试、配置、文档、日志或相似模块，只是为了更熟悉仓库时使用。本条用于打开一个无法对应具体判断的新来源之前。目标尚未定位时是近似场景，应先定位目标；已知来源对目标行为存在冲突时，应改用确认 authority 的 Practice。

## 具体指导

打开下一个来源前，先说清当前还没有解决的判断。只有当代码文件、测试、配置、文档、日志或相邻实现可能改变改动位置、责任归属、要求的行为、针对性验证，或是否需要重做计划时，才读取它。一次只沿着一个未解决的依赖继续查，并在每次直接观察后更新判断。若证据显示新增了重要的公开能力、共享状态、风险或验证需求，停止局部调查，依据这个新事实重做计划。不要把读过的文件数量、对仓库的泛泛熟悉，或穷尽调用方当作证据。目标行为、直接责任归属、改动边界和针对性验证路径都已明确，且下一个来源不会改变其中任何一项时，停止阅读。

## 反模式

用户要求把设置页保存按钮从灰色改成蓝色。Agent 找到页面，发现按钮使用一个共享变体，也找到了该变体读取的颜色 token。它本应判断 token 的语义是否允许局部覆盖或共享修改，却转而打开每个 Button 调用方、旧主题迁移、无关页面样式、大量端到端测试和架构说明。这些材料不会改变颜色选择，只会消耗 context，并让真正决定改动的两处来源被淹没。

## 原因

调查只有可能改变下一步判断时才有价值。读取不能改变判断的材料，会把不确定性变成拖延，浪费 context，并让无关观察与真正需要的少量事实竞争注意力。

## 例外与边界

工作环境已经提供的适用 instructions 应直接遵守。不要为了复现一个未知的发现机制而手工扫描仓库中可能存在的 instruction 文件。安全、权限、数据、兼容性、迁移、发布，或用户明确要求的审计可能需要更多调查，但每增加一个来源仍应回答一个已命名的边界问题。目标尚未定位时可以搜索；直接来源显示改动比已接受范围更大时，应重做计划，而不是继续无限扩张调查。

## 示例

用户要求修正发票预览里的货币标签。Agent 定位到预览组件，发现标签来自共享 formatter，随后只读取该 formatter 及其针对性测试。formatter 已接收带 locale 的货币代码，因此 Agent 修正一处标签映射并运行 formatter 测试；不会去读每个发票调用方或历史账单迁移。若 formatter 反而显示持久化的货币代码不一致，Agent 会停止并重做计划，因为任务已不再是局部标签修正。
