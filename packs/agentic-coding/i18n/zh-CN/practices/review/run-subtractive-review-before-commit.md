# 提交前删掉没有必要的改动

## 适用场景

完整 diff 已经能整体审查、即将 commit 或交接时使用。这里检查每项改动是否必要，不重新选择原设计，也不直接响应尚未验证的审查意见。

## 具体指导

对每项实质新增内容，指出是哪条需求、风险、已承诺行为或必要依赖支持它。删除没有当前理由的内容，合并重复逻辑，复用合适的现有代码；同时保留必需行为、迁移支持和保护措施。当 diff 已经是满足请求及其风险的最小集合时停止。任何删除改变了行为，都要在提交前重新验证。

沿本次修改涉及的路径，追踪一个代表性数据和一种失败。检查重复解析、规范化、鉴权、捕获后给默认值的封装和嵌套 retry：每项都需要独立条件和负责人。检查通用 guard 是否无必要地阻止 status、stop、升级或修复。只追踪改动行为，不把减法审查扩成全仓库审计。

## 反模式

上游路由守卫让服务层授权检查看似重复，恢复标记在正常路径也没人读。Agent 为缩小 diff 删掉两者，却保留惯用封装层和重复 parser。聚焦路由测试仍绿，但其他调用方能绕过授权，任务中断后也无法恢复。

## 原因

局部合理的新增内容在最终 diff 中更容易一起判断。减法审查用于去掉无依据的维护成本，不把行数少当成正确。

## 例外与边界

当前契约或发布过程要求的迁移、兼容、安全、审计和回滚代码应保留。改变已接受架构或公共契约前，要问有权决定的人。

## 示例

为分块图片上传做提交前审查时，Agent 删除未使用的进度抽象和重复媒体类型辅助函数，改用仓库现有 validator；保留上传契约要求的分块大小上限和残留文件清理，并在删除后重跑相关上传检查。
