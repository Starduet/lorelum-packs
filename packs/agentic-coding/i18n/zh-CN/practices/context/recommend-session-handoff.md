# 当历史上下文价值降低时建议换新对话

## 适用场景

当前工作还要继续，或用户准备进入下一阶段，但大部分历史都在讲已完成的调查、日志或不再采用的计划时，可以建议换新对话。只要简洁交接能保留后续所需的信息，就不必等到出错才提；旧方向也可能已经在干扰已接受的决定。如果已经确定要换会话，只需决定留什么记录，就编写检查点。

## 具体指导

1. 先明确接下来要做什么，包括剩余工作和已约定的下一阶段。选出决定这些工作的输入、承诺行为、数据处理、不同条件下的结果，以及准备收集或复用哪些证据的事实和条款。保留其中的限定，也说清是已接受、提议中还是尚待确认。不要逐个主题概述；无关或已被替代的历史不带过去，已知偏离约定的地方要纠正。下一个重点尚未选定，就说明未定，不要借交接替用户选好。
2. 一份短记录能够替代大量无关历史，或避免旧方向继续干扰时，就建议迁移。不必等到出错，也不要按对话轮数判断。历史仍有用且没有干扰，或工作即将结束、没有后续任务时，继续工作。
3. 写概述前，先列一份起草用的对照表：每条选中的原文条款，是直接写进交接，还是放在某个精确来源位置，并要求接收方在指定行动前读取。不要把起草表放进交接本身。

   每项独立义务、每个条件分支都要有去处，不能只留下主题名。例如，数据处理规则和凭据存储限制不能只用“隐私”二字带过。保留最小但完整的条款，包括条件、例外、结果，以及是否已经接受。转述可能改变要求或许可范围时，引用那一条，不要搬入整组规则。已接受的要求、提案和假设要分开；同意“继续讨论”不代表批准。

   保留实验证据时，对照表里不仅要有结果和局限，还要有实验方法及必须保持的控制条件。后面才用到的流程，可以留在可访问来源的精确位置，但那里必须保留相关规则和状态。只有文档名或整段历史链接不够。没有可用引用，就把必要条款写进交接，不必带上周围讨论。敏感值要删去。

4. 写一份紧凑的记录，说明目标、当前状态、决定、证据能证明到哪里、下一步，以及必要的来源位置。简短约束直接放正文。只有必要细节无法引用现有来源时，才另放一处供按需查阅，不要为每个主题再写一层概述。每项事实只写一次，开场指令引用这份记录即可。

   不知道当前事实，就说未知，不要重复过时快照。相邻任务只保留依赖关系，不展开计划，也不罗列省略了哪些工作。被否决方案的理由，只有仍会影响选择时才保留。不影响下一步决定的历史数字、目录清单和排错经过都省略。

5. 历史路径按来源原样保留。只有来源或明确检查确定了该项目根目录，才写绝对路径；当前工作目录本身不能证明这一点。根目录未知，就保留相对路径并说明未知，不要猜补。刚创建的交接文件，其实际位置是有效的新信息；要与历史产物的位置分清。无关环境和测试框架细节不必带入。
6. 用起草对照表逐条核对交接正文或精确的必读位置，确认原来的输入包含与排除范围、独立义务、条件、例外、结果、实验方法和控制条件都还在，决策状态也没有变化。主题标签、“保留契约”或可选的笼统来源索引，都不能补上漏掉的规则。

   不影响后续决定、必需行为或可执行的第一步的材料可以删除；决定工作要求的事实不能只为缩短篇幅而删掉。在工作稳定、适合交接的位置，说明换会话的好处，提供交接记录和可直接粘贴的开场指令。

当用户能够依据记录接续时停止。用户留在当前会话时继续工作；只有发生实质变化才再次建议迁移。

## 反模式

漫长的网关设计讨论结束后，实现只需已接受行为、约束和相关文件。Agent 等到出错才建议重开；随后又在背景、状态和完整开场 prompt 中重复同一设计，把被否决方案列为待选，并用当前目录补全历史相对路径。新会话继承了更多阅读负担和没有依据的项目位置。

## 原因

历史在明显偏移之前就可能增加阅读成本，并与当前指令竞争。交接只有在保留有效依据、避免重建全部历史或用编写者的环境填补缺口时，才能起到作用。

## 例外与边界

依据相关性判断迁移，长度或连贯性本身都不够。如果准备和加载交接增加的工作更多，就继续当前会话；一个阶段完成后仍可以交接下一阶段。独立粘贴的 prompt 需要足够上下文或可用的共用引用。先删除重复，再考虑删减必要约束；固定字数上限不能证明信息足够。文本变短本身不能证明总成本降低或后续执行更好。

## 示例

用户完成网关设计后要求实现。大部分历史是 tokenizer 实验和被否决的文本类型白名单，尚未发生错误。Agent 记录已接受的字节估算、预扣和完成后多退少补，以及排除已知文件载荷、保留其他内容的行为；只说明一次实现尚未验证，并保留白名单会低估的否决理由。历史路径 src/estimate.ts 的项目根目录未知，就保持相对。Agent 保存交接、提供实际位置，再给出读取交接后开始实现的简短开场指令，不再复述全部讨论。
