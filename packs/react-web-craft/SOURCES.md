## Excluded neighbors and scope decisions

- The archived `react.state.derive-render-values` candidate (card 1) remains rejected and its draft stays deleted. Under the Pack's distillation model the underlying source decision is in scope and is now covered by `react.rendering.derive-dont-mirror`, authored under the recalibrated acceptance bar (2026-09-14); the archived draft was not revived, and card 1's rejection record stands as history. `rerender-derived-state.md` (external-store subscription/performance) and `state-ground-truth.md` / the derived-value portion of `react-state-minimize.md` remain excluded by scope.
- The manual-memo cluster (`rerender-memo.md`, `rerender-memo-with-default-value.md`, `rerender-simple-expression-in-memo.md`, `rerender-split-combined-hooks.md`, `rerender-no-inline-components.md`) is deferred: whether hand memoization pays depends on measured hot spots and React Compiler behavior, which the sources' blanket claims do not carry; one measured memoization practice may follow.
- `rerender-dependencies.md` and `rerender-defer-reads.md` are deferred: Effect dependency expression and external-subscription choices belong to an Effect-design decision this Pack has not yet opened.
- `rendering-hoist-jsx.md` is deferred: hoisting constant JSX is a micro-optimization whose value is compiler-era dependent, with no measured trigger recorded.
- `rendering-activity.md`, `rendering-content-visibility.md`, `rendering-svg-precision.md`, and `rendering-animate-svg-wrapper.md` stay deferred or excluded: version-sensitive (Activity), CSS-scoped (content-visibility), tool-dependent (SVGO), or resting on an unverified hardware-acceleration claim (the SVG wrapper).
- `state-context-interface.md` and `state-decouple-implementation.md` are deferred: provider dependency-injection contracts need a frequent, independently retrievable trigger; they are neighbors of `explicit-variants-over-flags`.
- `react.state.event-triggered-work` remains rejected after direct comparison with `rerender-move-effect-to-event.md`: trigger, recommendation, failure mechanism, and core boundary match. The print example did not create a distinct decision; the candidate card in `drafts/react/CANDIDATE-CARDS.md` is its tombstone.
- `react-state-dispatcher.md` and `rerender-functional-setstate.md` both recommend a functional updater when next state depends on pending state. The Pack keeps the accepted narrow updater-capture decision and does not create a general second updater Practice. Their respective React Native layout and React DOM callback examples do not create distinct state semantics.
- `advanced-event-handler-refs.md` and `advanced-effect-event-deps.md` concern handler/latest-value or Effect dependency behavior, not where React DOM component state belongs. They do not authorize a generic latest-value ref recommendation.
- `rerender-defer-reads.md` is a dynamic external-state subscription choice, not a local component-state model. `server-no-shared-module-state.md` is a server request-isolation concern. React View Transitions, React Native/Expo UI rules, list performance, rendering priority, and application state-library selection remain outside this Pack.
- `state-decouple-implementation.md`, `state-context-interface.md`, and compound-component rules address provider abstraction, dependency injection, or component API architecture. `share-one-owner` only borrows these as nearest neighbors; it does not prescribe those architectures.
- Other React Best Practices rules are not converted one-for-one. Inclusion is based on a distinct React DOM decision, not source-rule count or source-declared impact.

- `async-api-routes.md` is a Next route-handler wrapping of the same scheduling principle stated in `parallel-independent-work`; route-handler-specific guidance stays deferred, so no separate Practice exists for it.
- `server-parallel-fetching.md`'s composition principle — a parent that does not await lets sibling subtrees start together — is absorbed into `suspense-boundary-scope`; its deeper RSC-tree rendering-order claims stay deferred pending framework-version verification.
- The `better-all` helper recommended by `async-dependencies.md` is not required: the Pack states the dependency-free promise-chaining equivalent, and adopting a helper library is a project decision, not Pack guidance.

- `bundle-barrel-imports.md` is deferred, not adopted: whether barrel-file entry points cost real time depends on the package's `exports` map, bundler, and externalization, so a blanket ban is not written; revisit with build-output evidence per project.
- `server-dedup-props.md` and `server-serialization.md` are deferred: the claim that RSC serialization deduplicates by object reference, and the resulting move-transforms-to-client advice, could not be verified against public React documentation; the general data-minimization idea is left to a future practice argued independently.
- `server-cache-lru.md` is deferred: a module-level LRU is per-process, not cross-instance, and its safe use needs tenancy-aware keys, eviction, and invalidation design that a short rule cannot carry.
- `server-after-nonblocking.md` is deferred: `after()` is Next-specific and its execution guarantees (static prerendering, request lifetime, platform limits) need version-pinned verification before any practice states them.
- `server-hoist-static-io.md` is a read-only-configuration neighbor of `no-module-request-state`; deferring it keeps that Practice's allowlist guidance independent of Next-specific static-asset tracing behavior.
