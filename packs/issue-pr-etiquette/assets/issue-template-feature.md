# Feature / proposal issue template

Copy this skeleton to the task workspace and fill it in; adapt section order to the repository's
own template when one exists. Write in the repository's collaboration language; keep commands and
identifiers in their original spelling. For the full writing decisions behind each section,
retrieve the `issue-pr-etiquette.issue.*` Practices.

**Title:** `<one problem, stated as a gap>`

## The problem

What cannot be done today, or what is painful? Who does this affect?

Cite the concrete occurrences: incident links, prior issue numbers, failing runs — each with a
one-line role. Separate observed facts from your interpretation.

## The proposed direction

What should change? State the objective and the principles any solution must satisfy. This issue
establishes the direction, not the implementation design.

## Non-goals

Name the decisions deliberately deferred (storage, schema, rollout, …) and where they will be
decided.

## Acceptance criteria

When is this done? Bullet the testable outcomes; each item must be checkable by someone who is not
the author.

- [ ] <observable behavior / artifact that exists>
- [ ] <observable behavior / artifact that exists>

## Related work

- #<n> — <one-line role: evidence it recurs / prior attempt / constraint to respect>

## Confirmation

- [ ] I searched existing issues and Discussions and this is not a duplicate.
- [ ] I understand this is a proposal — maintainers decide if and when it is picked up.
