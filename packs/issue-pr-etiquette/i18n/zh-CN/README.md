# Issue 与 Pull Request 礼仪

`issue-pr-etiquette@0.1.0` 是一个面向贡献者和 Agent 的领域中立知识包，使用场景是在 GitHub 托管的工程仓库中提 issue、开 pull request 和参与评审。每条 Practice 固化一个反复出现的决策：一个 issue 应当只拥有什么问题、什么证据能支撑它、PR 正文如何写得可验证、评审反馈与 AI 辅助如何诚实地沟通。

Canonical English · 当前为简体中文配套阅读版

## 适用范围

准备提交 bug 或功能 issue、判断一个变更是否需要先有 issue 或设计对齐、组织或命名 PR、为陌生评审者撰写可验证的 PR 正文、避免私密材料进入 diff、回应评审反馈、披露 AI 辅助与 AI 审查发现时，使用本 Pack。

本 Pack 的 Practices 由 Lorelum 系仓库的贡献规范与优秀范例泛化而来。仓库专属机制——OpenSpec 变更门禁、双轮评审协议、分支命名方案、冻结规则——被有意排除在 Practice 本体之外，集中收录在[贡献门禁图](resource:references/contribution-gate-map.md)。可直接复用的发帖起点以模板形式附在 `assets/` 中，由需要它们的 Practice 链接。

## 非目标

本 Pack 不是 GitHub 教程、不替代任何仓库自己的贡献指南、不是执行工具、也不是流程框架。它不为所有仓库规定同一种分支命名或评审轮次方案；遵循全部 Practice 也不保证被接受——是否采纳由各仓库维护者决定。作为附件提供的模板是待改编的起点，不是强制表单。

## 发布历史

- `0.1.0` 为首个版本。只有在 canonical 内容、本地化与 fixtures 均验证通过后才创建 tag；只有该 tag 通过官方 Registry 路径安装成功后，才声称可安装。
